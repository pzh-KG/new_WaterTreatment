新增证据与时间语义的通用局部复审
日期：2026-11-18

适用范围
本次修改共享的审查范围编译、来源复核、续审认证和最终结果准入流程。新文献与已有候选的恢复均使用同一规则，不依赖论文序号、DOI、材料名或预期科学答案。科学抽取规则仍为 0.8，模型仍为 gpt-6.1-sol / max；局部审查编译器版本 3 不代表科学抽取规则升级为 3。

新增证据
允许在既有 evidence 列表末尾追加证据。既有证据的顺序、ID、引文和来源定义不可借此改写。新 ID 必须唯一，不能给同一证据换名重复添加，也不能悄悄填补旧记录中悬空的证据引用。
新增证据必须来自该文献已登记且覆盖记录未变化的来源/块，并支持本次真正修改的结构化事实或证据关系；孤立新增项不予接受。
局部复审冻结新增证据、使用它的修改、受影响实体、旧疑点和来源锚点。来源文件哈希、块和页码仍需核验，模型仍须实际回查来源并分别审查新增证据与相关结论。能定位到原文不等于原文支持该结论。
仅替换引用、且事实的数值、状态、单位、解释和候选含义均保持一致时，不应把未改变的全部下游实验重复判为科学修订。被修改对象及新旧证据仍必须复审，直接消费者保留在上下文中；存在非引用字段的旧疑点或任何实质语义变化时，仍沿原依赖范围审查。这一边界只用于 v3，不改写历史审查。

时间语义
实验或观测的 time_window.kind 改变时，把完整的新旧时间对象作为一项变化冻结，连同 reference、start、end、unit、依据和歧义一起复核，不能只审一个标签。
受影响的观测、实验、共同参考组、性能配对和查询适用性仍进入依赖检查。时间标签修订不能成为修改主要数值结果、材料身份、实验归属或阅读覆盖的通道；原有冲突与候选解释不得偷偷删除。

适用性限制
局部修订可为本记录已存在的对象追加带原因、限制说明和原文依据的 limited 用途记录，新增记录及受影响目标进入复审。用途、目标类型和目标 ID 的组合必须唯一；旧记录身份和顺序不变。这一入口不允许新增 eligible 权限或借新增记录放宽限制，旧编译器版本仍维持原边界。

审查与恢复
局部复审必须建立在可认证的已完成原文审查之上。保留完整首审、全部修订和审查链，只对累计变化及其必要上下文重新核读；不能把中断的旧审查当作已完成证明。
新增运行明确冻结编译器 v3；历史 v1/v2 的已完成审查按其原版本复现、认证。不能以新规则重新解释旧证明。旧运行产生的可认证修订稿，可另建使用 v3 的续审运行，旧运行保持不变。
理解档案尚缺阅读处置记录时，可先保留缺项完成科学局部复审，但缺项仍会阻止最终自动完成。修好编排代码不会把失败文献直接改成“完成”。
超出局部复审能力或范围上限时保存候选和具体原因；不自动回到整篇抽取或整篇重审，不靠延长超时放行。

后台版本与任务队列
网页后台启动时记录实际应用目录的代码树快照，状态接口分别显示启动快照、当前磁盘快照、PID 和启动时间。它是文件系统版本检查，不是 Python 内存的逐字节认证。
发现代码、提示词或共享配置变化后提示重启，并阻止新模型任务进入执行。只在任务尚未执行的派发前检查中发现旧代码时，原任务保留为排队并暂停队列，不伪造失败、不消费新的恢复授权。运行中已经开始工作的任务不能因此伪装成“尚未执行”。
重启后可按原任务继续；旧结果、错误和科研记录保留。原始文献、输出及运行数据仍在已配置的数据根目录，后台不自动写入 Neo4j。

验证边界
官方离线检查入口：scripts/quality/run_offline_regression.py。合成测试覆盖新增证据、时间语义、来源伪造、未实际核读、漏处置旧疑点、旧版本证明及队列暂停恢复。
真实开发文献的离线回放只检查范围构造、来源定位及旧版本兼容，不是新的模型审查或科学验证。相关文献按开发数据记录使用历史。模型抽取准确率和全流程时间仍需独立、明确范围的真实评估。
