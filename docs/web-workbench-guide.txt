WaterTreatment 本地网页工作台使用说明
2026-11-12

一、从哪里启动

工程目录：D:\new_WaterTreatment
代码环境：D:\new_WaterTreatment\.venv\Scripts\python.exe
实际配置：D:\new_WaterTreatment\config\project.local.json
研究数据：D:\new_WaterTreatment-data
网页地址：http://127.0.0.1:8765
新图数据库：本机新实例的 watertreatment；实际连接以 project.local.json 为准。

方法一：双击 D:\new_WaterTreatment\scripts\start-web.cmd，保持窗口打开。
方法二：在 PyCharm 打开 D:\new_WaterTreatment，选择工程自己的 .venv 解释器，在终端运行：

.\.venv\Scripts\python.exe -m watertreatment --config config/project.local.json web --host 127.0.0.1 --port 8765

也可在 PowerShell 中运行 .\scripts\start-web.ps1。若系统限制执行 PowerShell 脚本，使用 start-web.cmd 或上述 Python 命令，不必更改机器的执行策略。

方法三：创建 PyCharm 的 Python 运行配置：
模块名称：watertreatment
参数：--config config/project.local.json web --host 127.0.0.1 --port 8765
工作目录：D:\new_WaterTreatment
解释器：D:\new_WaterTreatment\.venv\Scripts\python.exe

启动后，在浏览器输入网页地址。启动本地网页不等于提交抽取、问答或图谱写入；网页展示已有来源、记录与历史任务。服务重启时，历史排队任务保留并暂停，上次运行中的任务标为中断；需要继续时，在“抽取任务”页检查后继续队列或重试。新空队列不额外暂停，可正常接收你新提交的任务。不要把扫描根目录或启动全库抽取设为首次试用动作。

网页依赖属于项目的 web 可选依赖。如果启动提示缺少 fastapi 或 uvicorn，在当前工程虚拟环境安装项目依赖，使用 README 中的锁定依赖流程；按可选依赖安装可用：
.\.venv\Scripts\python.exe -m pip install -e ".[web]"
不要覆盖已有 project.local.json，也不要复制旧工程的环境或数据库配置。

需要入库或使用图谱当前记录问答时，先启动已配置的新 Neo4j 实例。仅查看文献和结果不需要连接数据库。模型使用固定 gpt-6.2-sol / max，沿用后台已有正常登录，不在网页输入模型或数据库密码。任务调用不承诺在 Codex 桌面侧边栏生成一条可见聊天。

关闭浏览器不会终止仍在运行的后台服务。要停止服务，回到启动终端按 Ctrl+C；停止后台后，运行中的模型任务可能中断，已有产物仍保留，重新启动后检查任务状态，不把中断当作完成。运行时不应同时启动多个相同工程服务。

二、六个页面

1. 总览
查看文献登记、自动处理完成、当前入库、局部人工抽查的数量，以及最近结果和需要注意的事项。不同数量代表不同阶段，自动完成不等于人工验证。设置入口展示运行环境和使用说明，不展示凭据。

2. 文献库
管理“序号_热催_期刊名”文件夹中的正文和 SI。点击“扫描文献目录”，在弹窗中选择已配置的文献根目录，直接勾选需要扫描的子文件夹；不用逐篇填写路径。当前已配置 D:\桌面\work\知识图谱进阶\数据库文献\文献。
列表显示序号、文件夹名、支持的附件数量/格式、登记状态和是否已有抽取结果。支持按名称、序号或序号范围（如131-176）搜索、“只看未登记”、全选当前筛选和清除已选；默认不勾选任何文献。筛选后已有选择仍保留，界面会提示隐藏的已选数量；更换根目录会清空选择。单次最多500篇，超过上限会提示缩小选择，不静默截断。
打开列表只枚举直接子文件夹及文件名，不解析正文、不新增文献任务；不可用目录会提示，无PDF/DOCX/DOC附件的文件夹不能勾选。点击“扫描选中文献”只扫描所选路径并登记到文献库。扫描登记、模型抽取和发布到Neo4j是三个阶段，扫描不会自动发起后两项。首次试用仍选择少量已有开发文献。
扫描只做文件登记和有限内容识别，不做科研全文抽取。PDF 使用起始页与末页、Word 使用有限起始段落帮助识别；不是已经读懂全文。
保留原文件名，不必统一改成 main_article 或 supporting_information；Word SI 保留 DOCX。文件名是线索，内容结构和与正文的身份关系共同参与判断。
打开待确认附件，查看角色、判定理由和预览，再选择正文、SI、合并正文与SI、无关文件或仍不确定。确认角色不代表确认科学内容。多个SI可以属于同一论文，不要求每个SI都印有同样DOI。
已识别为SI但只有同文件夹线索、正文候选不唯一、标题/DOI冲突、混合内容或内容无法读取时，保留需要确认状态。明确的身份冲突不会因为简单点击“这是SI”而消失；应核对下载归属，必要时将确属其他论文的文件排除。原文件仍保留。
字节完全相同的重复附件只读取一份；正文与SI合并文件经明确确认后仍作为一个真实来源，不制造虚假的内部页码分界。无SI可抽取已有正文，并保留来源不足；旧DOC与不可读附件需确认或提供可读取的衍生格式，不能假称已读。
附件新增、替换或角色改变后重新扫描。人工角色确认绑定文件内容指纹，替换的文件不能继承旧确认。

3. 抽取任务
在文献库勾选少量文献并启动抽取，选择相应处理与入库策略。未确认关键附件的文献不能直接开始；其他已确认文献可继续。明确是否自动入库后，不要求每篇再人工审批。
后台依次完成来源快照与解析、全文理解、候选抽取、原文审查和有预算的自动修订。任务页展示排队、正在处理、完成、未完成、中断或失败，以及已保存阶段。
首次试用继续使用已有开发文献，不启动393篇批处理。修改过规则的文献仍是开发数据，不能改称独立验证。
暂停队列暂停后续派发，不等于强制杀掉正在处理的文献；可取消排队任务，失败或中断任务按页面提供的方式重试，旧任务和失败记录保留。关闭网页后后台任务仍可继续，前提是启动终端和服务还在运行。
批量抽取弹窗可统一设置本批单篇初始额度、每次追加额度、自动追加次数和累计上限。未完成任务中的“追加额度并继续”会先展示可核验的消耗与恢复阶段，确认后才执行。完整说明见 docs/budget-continuation.txt。
“机器错误0”或“最终模型未要求再修订”仅说明相应检查没有再发现问题，不能证明科学内容全部正确。预算耗尽产生的候选不冒充已完成结果。

4. 人工抽查
仅选少量文献。可从抽查清单进入，也可在结果页主动选择一篇，不要求393篇逐篇审阅。每篇优先看最终材料、蒸发与催化核心结果、稳定性和主要图表；前驱体或对照只在解释最终材料或定位归属时辅助查看。
工作台一侧显示正文/SI证据与预览，另一侧显示当前材料、实验、指标、条件、缺失状态和已有问题。图像可放大；Word按段落、表格和图片实例定位，不虚构物理页码。

建议每篇这样做：
（1）先看论文与最终材料身份，确认当前打开的是需要抽查的记录版本。
（2）从少量主要结果卡开始，点击证据，回到原图、表或相邻文字。
（3）勾选本次实际核查范围：初版表单提供数值/状态、单位、材料归属、实验归属、时间窗口。指标含义、复杂条件、同步/配对和稳定性疑点可在备注中指出并请求模型回查。只核对了数值，就只确认数值，不能连带确认整组条件。
（4）选择“与原文一致”“需要修正”“已核查来源未报告”“原文存在冲突”或“暂不能判断”。修正、缺失或未解决的判断写明原文位置和简短理由。
（5）需要补抽条件、新增证据、修改时间窗口或发现遗漏时，写清问题并请求模型定向回查；不必手填完整JSON。也可从主要图表开始进行反向查漏，指出遗漏的最终材料、实验或结果。
（6）检查本次提交范围，填写审核人并提交。草稿自动保存与最终提交是两件事；只浏览证据、保存草稿或模型再次赞同均不算人工确认。

初版直接编辑支持数值、单位、已有材料归属和已有实验归属。复杂条件、时间窗口、新证据或新实体通过模型回查处理。修改材料/实验归属会影响条件和成对结果，需要重新检查相关关系。
“未报告”只用于确已核查来源中找不到的数值/单位；SI未取得、尚未读到或图像看不清应记录限制，不能伪装成作者未报告。缺失不填0。
原文冲突记录双方位置和内容，交给回查保存冲突证据，不任取一个更高值。暂不能判断也可以提交其他已核查项目，未判断项不会算成正确。
人工确认增加限定范围的审核记录；事实修正产生新的JSON版本，原值、原输出和历史结论继续保留。模型建议若与明确的人工作出结论冲突，不得静默覆盖。新版本改变了被核查内容时，旧结论不能自动套用。
系统保存审核人、时间、对象、字段、证据、理由和版本，因此知道“什么内容被人核过”；不根据你打开过文件就推断人工审核。human_validated=false仍可与“部分内容已核查”并存，因为没有宣称整篇已经人工验证。
人工抽查不会训练或改变Codex权重；重复性错误可以另行形成规则改进并版本化验证。少量抽查通过不能直接计算全库准确率，没建立完整原文目标清单也不能宣称整篇召回率。

5. 数据与入库
查看最终材料—实验—观测与相应证据，区分最新JSON版本与图谱当前有效版本。完整JSON、证据和审核历史留在记录层，Neo4j承载检索所需对象、关系及状态。
可下载JSON；需要修正时通过抽查/回查生成新版本，不能只修改Neo4j里的数值而让JSON与证据仍停在旧版。
下载的是当前打开版本的全部抽取记录，不受页面指标筛选影响；它不包含全部历史版本/运行日志，也不证明论文每个图表点已经完整抽取。图上估读值显示“≈”与独立标记；“审查与限制”页另列图表定量覆盖，旧记录无清单时明确提示未登记。规则0.6细节见docs/quantitative-coverage-0.6.txt。
发布前检查来源指纹、对象关系、自动审查与完成状态。不要求每个字段有数值，也不要求每篇先人工审核。缺失或局部限制如实保留；未完成、有待复审或不符合准入的版本不会伪装为正常可用记录。
选择“同步/发布到Neo4j”后写入明确配置的新watertreatment库。新版本成功写入后才更新当前有效快照；失败保留旧快照与错误记录，可重试同步，不需要重复全文抽取。相同版本重复发布不会重复计数。
人工提交成功不等于已经入库。旧版本与当前JSON不一致或来源已改变时，应以页面的待更新状态为准，问答不能继续把已知过时版本当作最新有效结论。

6. 文献问答
先选择范围：所选论文结果，或图谱当前有效记录。所选结果问答可以包括尚未入库的最新候选，界面会保留范围；图谱模式使用当前有效快照，不将同篇多版本重复计数。
问题示例：这些最终材料分别用什么催化剂/氧化剂处理什么污染物？它们的蒸发率和催化结果是否来自同一组同时运行实验？哪些稳定性结论有原文支持？
回答结合记录与必要原文回查，附记录/证据引用。点击引用查看来源和实验；保存的问题、答案和版本可追溯。引用编号存在或能定位到原文，不等于结论的科学准确性已经验证。
系统必须区分去除、降解、矿化和冷凝水质量；条件和时间不同的结果不能直接排高低；不能把独立最优蒸发率与催化效率拼成一组；缺失值不代表0或条件相同。同步运行证据与数值配对依据分别判断。
设计建议与论文实测分开，回答应说明证据范围与限制。首版不自动引入库外网页事实，也不宣称已经完成可靠材料推荐、因果规则发现或393篇降维分析。
问答只读，不直接改JSON或图谱。发现疑点通过定向回查和版本流程处理。

三、遇到问题时

打不开网页：确认启动终端仍在运行，地址是127.0.0.1:8765；查看终端是否提示端口被占用或依赖缺失。不要直接终止未知进程，也不要为了使用工作台去关闭旧Neo4j实例。
附件无法继续：查看是文件角色未确认、论文身份冲突、来源变化还是格式/文字不可读。确认文件角色与确认科学内容是不同操作。
抽取失败：先看任务阶段和保留的错误，解决登录、来源或配置问题后重试。不要降低模型或覆盖失败产物。
入库失败：结果仍在记录层，确认新Neo4j已启动和明确连接配置后重试发布。不要改旧实例。
提交抽查提示版本改变：刷新并比较最新结果再提交，避免旧页面覆盖新记录。
提出新功能：保留现有来源、版本和审核历史，在此基础上扩展规则和界面；分类、降维与材料开发路径属于后续功能，不把初版数据整理直接等同于可靠设计规则。

本说明描述当前功能流程与边界，不是全库科学准确率报告。真实运行与验收结果应分别记录模型版本、来源指纹、处理范围与发现的问题。
