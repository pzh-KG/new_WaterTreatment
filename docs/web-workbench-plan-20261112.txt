WaterTreatment 网页端功能与操作规划
版本：规划草案 v1.0
日期：2026-11-12
用途：作为后续页面、后台任务和数据流程实现的共同依据。本文件仅为规划，不表示相关网页或新增功能已经实现，也不启动393篇处理或数据库写入。

一、目标与使用方式

建立一个本机运行、通过浏览器使用的研究工作台，将文献附件识别、全文抽取、少量人工抽查、数据入库与证据问答放在同一套界面中。首版以当前研究者使用为主；多人协作和远程部署留待后续需要时再扩展。

研究重心是同一体系中同时实现蒸发与污染物降解/高级氧化的最终双功能材料。覆盖全部材料类别，以蒸发速率、催化效果和稳定性为主要结果。前驱体和对照保留必要信息，默认不抢占最终材料的展示位置。

模型负责主要阅读、抽取、主动回查与自动修订。人工仅确认少量确实有歧义的附件角色，并在批次完成后抽查少数论文；不把393篇都变成人工审批任务。正常文献不需要手写角色映射，不需要逐字段补齐数据，也不以人工审核作为常规入库必要条件。

继续固定使用 gpt-6.1-sol / max。网页复用现有主动阅读能力，不退化为只读摘要或只把文本片段交给模型的一次性抽取。模型调用、来源读取和图像处理继续保留可追溯记录。

未报告、未取得、未读、不可读、已读未量化、冲突、不适用、明确没有和模型推断保持区别。文献没有写的条件不要求模型编造；普通缺失不自动触发人工任务。不同工况的最优值不能拼成一组“双功能最佳性能”。

默认工作路线：
选择文献目录 → 自动识别附件 → 启动自动抽取与审查 → 形成版本化结果 → 按批次策略入库 → 数据问答。
少量人工抽查从已完成结果中分支进行，可在入库前或入库后完成，不串行阻塞全部文献。
抽查修正 → 新结果版本 → 校验与必要回查 → 同步当前图谱版本 → 后续问答采用新版。

二、当前能力与待开发范围

可复用的现有能力：
1. 单篇文献导入、原件快照、PDF和原生Word解析、PDF页图与Word插图读取。
2. Sol MAX连续阅读、最终材料与实验关系梳理、结构化抽取、回查、图表放大、新会话审查及有预算的自动修订。
3. 来源、规则、模型配置与输出版本留存；机器一致性检查；每篇少量结果抽查TXT。
4. 注册候选的本地投影与Neo4j显式加载；有限人工评测数据结构。

需要新增或完善：
1. 本规划全部网页、任务调度和进度展示。
2. 正文/SI自动识别、同篇归属核对、混合文件范围识别和少量确认入口。
3. 面向生产批次的队列、单篇失败隔离、恢复和统计。现有试跑脚本只接受1—3篇已登记开发文献，不能当成已有393篇生产调度器。
4. 人工核查提交、字段修正、新JSON版本生成和审核记录联动。
5. 入库前的自动审查完成检查、图谱当前有效版本切换、更新失败恢复。
6. 基于图谱、完整记录和原文证据的问答。

当前graph-load检查注册来源、结构与关系，不要求human_validated=true，但尚未强制读取result中的审查完成状态。后续统一准入需要补齐，不能仅给旧命令套一个网页按钮就称为完成全部质量流程。

三、全站结构与状态表达

左侧固定导航：总览、文献库、抽取任务、人工抽查、数据与入库、文献问答。设置与运行诊断放在次级入口。文献详情、原文阅读和版本比较作为这些页面可共用的详情视图，不重复建设。

顶部显示当前研究项目、批次切换、全局检索、后台任务状态。正文区域显示科研内容，运行ID、哈希、内部字段名和详细调用日志放在可展开的技术详情中。

四组状态分别展示，不合并成一个“通过/失败”：
附件状态：已识别、待确认、缺少正文、部分附件未取得、归属冲突。
自动处理状态：待处理、准备中、理解中、抽取中、审查中、回查修订中、完成、完成但有限制、未完成、失败。
人工抽查状态：未抽中、待抽查、已保存草稿、部分内容已核查、已提交修正。旁边注明核查范围和版本。
数据状态：未入库、待同步、已入库、有新版待同步、同步失败、旧版已替代。

“未经人工抽查”和“作者未报告”使用中性样式；确定的抽取错误、来源归属冲突和执行失败才突出提示。颜色始终配文字，不能只靠红绿判断。

网页中的“完成”表示所要求的自动流程完成，不表示论文所有内容都已证明正确。进度按真实阶段和已完成任务计数，不编造模型思考百分比。

四、总览页

布局：
顶部为批次与范围选择；中部为文献数量和阶段统计；下方左侧为任务进展，右侧为需要用户采取行动的少量事项；底部为近期入库和版本变化。

统计卡展示：已登记文献、可进入抽取、已完成、完成但有限制、未完成/失败、当前已入库、已抽查论文数。393是研究候选范围，不把未下载或不适用文献算作已完成。

待办分两组：附件归属/角色待确认；已入选的科研内容抽查。普通缺失、未被抽中的论文和保留的原文冲突不自动生成393条待办。

操作：进入文献库、选择批次开始处理、暂停后续队列、继续队列、查看失败、生成少量抽查清单、进入问答。暂停队列默认停止派发新论文，当前论文继续到安全保存点；用户另选中断当前任务时，保留已完成产物和未完成状态。

本页不能通过一个“全部成功”数字掩盖失败、未处理或附件未取得。随机抽查样本与复杂案例样本的结果分开展示，不给出未经统计支持的全库准确率。

五、文献库与附件自动识别

5.1 文献库布局
顶部：选择本机文献目录、扫描新文件、搜索标题/DOI/文件夹序号、批次选择。
左侧筛选：年份、期刊、附件状态、处理状态、开发/保留验证/普通待处理角色。
中央列表：文件夹序号、标题、DOI、年份、期刊、正文/SI数量、附件状态、自动处理状态、最近结果版本。
右侧详情：文献身份、附件列表、原文预览、历史变化、进入抽取或已有结果。

本机目录通过本地服务的受限目录选择/配置入口登记，浏览器界面不假装能直接读取任意Windows路径。原文件继续放在原来的“序号_热催_期刊名”文件夹内，不改名、不转换或删除原件。

文件夹序号仅帮助定位，不作为唯一论文身份。文献身份结合已有题录、正文首页标题/DOI/作者等核对；参考文献中的DOI不能直接当作本篇DOI。准确匹配不到时保留原文信息和待核对状态。

5.2 自动识别流程
第一步，枚举附件并计算内容指纹，识别完全相同的文件副本；同一论文的不同版本或衍生文件保留关系，不自动删除或算成独立文献。
第二步，从文件名、首页或起始结构块、文档属性、标题、补充材料声明和图表编号取得线索。main、SI、supporting、supplementary、mmc等只是线索，Word格式或存在图S1都不是单独决定依据。
第三步，综合核对正文结构、补充内容特征、论文身份与附件间对应关系。常规线索足够时自动登记，复杂情形可调用受限内容识别；不为判断角色提前启动完整科研抽取。
第四步，输出建议角色、证据位置、理由和是否存在冲突。自动通过取决于可验证证据的一致性，不仅依赖模型自报置信度。具体阈值在已有文献上校准，规划阶段不先定“95%即通过”。

角色包括正文、SI、其他相关附件、暂不确定；重复和不同版本另作文件关系记录。多份SI关联到同一论文。综述/实验论文是论文类型，与正文/SI角色分别判断；题录Article不自动保证是实验研究。

正文和SI合并在一个文件时，识别文件内页段或结构块范围，显示“正文+SI合并文件”。保留同一来源文件身份，不要求用户拆分，也不把两个范围当成两份独立证据。

5.3 待确认页面
将所有确实不确定的附件集中到“附件待确认”列表；每项展示所属论文、原文件名、首页/起始块预览、建议角色、判定证据和冲突原因。
动作：确认为正文、确认为SI、标记其他附件、调整所属论文、暂不确定。能看到上一项/下一项和本次提交范围，不要求手写映射文件。
支持对证据一致且确实同类的选中附件统一确认，逐项显示受影响文件；归属冲突不能被无差别批量确认。
正文身份明确、SI尚未取得的文献可以按“只覆盖已取得来源”抽取；角色或归属不清且影响来源范围时暂挂该篇，其他文献继续。不能为了少问用户而静默忽略不确定附件。
若大量附件均落入待确认，应先改进识别/解析并自动重试，不能把全部判断转嫁给人工。

5.4 新增附件和角色纠错
新增SI、原件内容变化、纠正角色或合并范围，都形成新的来源版本，保留旧来源登记和结果。
详情页明确显示“现有结果尚未覆盖新附件/新角色信息”，列出建议回查范围。旧结果仍可查看，但不会自动宣称已经读过新SI。
如果仅修正展示名称且来源内容与科学归属不变，可只更新显示信息；任何涉及证据范围或归属的变化均需评估结果影响。

六、抽取任务页

布局：顶部为选中文献、任务范围与批次设置；中央为任务队列；右侧为单篇阶段详情；底部为运行事件、输出和失败信息。进入某篇后展示其来源清单、材料/实验概览、已完成阶段和下一步。

启动前显示此次论文清单、已取得正文/SI、数据集角色、固定模型与推理强度、单篇预算和完成后是否自动入库。用户选择一次批次策略，不逐篇弹出审批。

后台阶段：来源登记与阅读准备 → 正文/SI联合理解 → 最终材料和实验结构化抽取 → 机器校验 → 新会话回源审查 → 按问题修订 → 再审查 → 保存当前结果与限制。

结果内容重点：
最终材料及变体、组成/化学类别/形态/功能角色/来源分类、必要制备路径与结构设计；污染物身份及浓度；催化剂/活性组分、氧化剂及来源和剂量；装置和反应条件；蒸发、催化与稳定性观测；原文证据和缺失/冲突状态。
每个数值绑定具体材料、实验、时间、采样相和指标语义。对照与前驱体默认折叠，可在解释材料设计或比较结果时展开。
同步运行和数值配对分别表达；图表估计值与作者报告值分开。读取覆盖、内容理解和结构化完成分别登记。

模型使用已具备的原文重读、跨正文/SI检索、PDF局部重绘和Word插图放大。合理核查相关方法、图注和已取得SI后仍未找到的条件，可登记为已取得来源中未报告，不无限重试、不补常识默认值。

结果分流：
完成：自动审查已结束，可进入准入校验。
完成但有限制：缺失或冲突已忠实记录，可在保留使用限制的前提下进入准入校验。
未完成：达到预算或部分必要步骤没完成，保留产物，不能当成普通完成结果入库。
失败：记录具体原因，支持恢复已完成阶段或新建重试任务，不覆盖旧运行。

生产队列中单篇解析或内容问题不应使其他无关文献全部停止；账户调用不可用、磁盘不足、共同配置错误等系统问题则暂停继续派发，避免连续失败。重试有次数/预算上限，不自动降低模型。

长任务由后台持久化队列执行，关闭或刷新浏览器不取消任务。主机重启后区分“已完成阶段”和“中断阶段”，按来源与版本检查恢复，不能把部分输出标成完成。首版以稳定顺序运行或经验证的有限并发为主，不预先承诺393篇耗时。

七、人工抽查工作台

7.1 工作量与抽样
入口只列入选文献，不把所有未人工核查的论文列为待办。默认在批次处理完成后生成少量样本，也支持用户主动选篇。
可以先采用6篇作为可调整的工作量示例：4篇随机、2篇覆盖复杂图表/Word SI/显著歧义。随机样本与目的性样本分别标记；保存抽样总体、方法、时间、种子和替换原因，避免只挑容易或成功的论文。
随机科研核查样本的总体应明确是已形成结果的论文；未完成/失败论文在完整批次统计中保留，并可单列诊断样本，不把它们偷偷从完成率分母删除。
C01—C04和原V01—V10属于开发数据，不再作为独立验收样本。根据某个样本修改规则后，记录其开发暴露历史，不能拿修好后的同一篇证明新版泛化准确率。

每篇默认呈现最多6项核心结果，相关条件随结果展示，不拆成几十个必填审核任务。成对蒸发/催化结果可同屏显示，但明确计为两个观测；实际核查范围按观测及被核字段记录。支持少于6项、部分提交、跳过或主动展开其他结果，不要求凑满数量。

7.2 页面布局
顶栏：标题、DOI、文件夹序号、当前材料、抽取版本、自动审查状态、图谱当前版本、当前抽查进度。
左侧窄导航：最终材料/变体 → 实验 → 本次抽查项。前驱体、对照和未选中结果默认折叠，允许展开。
中间宽区域：原文查看器，正文/SI切换、定位、上下文、图表放大、不同证据并排、返回上一位置。
右侧：当前结果卡、条件和证据绑定、人工结论及修改区。
底部固定操作：保存草稿、提交本次已完成核查、上一项/下一项。不存在默认“整篇全部通过”按钮。

示意：
┌──────────────── 标题 DOI 版本 状态 本次核查范围 ────────────────┐
│ 材料与实验导航 │         原文与图表阅读区域         │ 当前结果卡与操作 │
│ 最终材料优先   │ 正文/SI切换、上下文、放大、双证据 │ 数值、条件、归属 │
│ 本次抽查项    │ 原文定位与人工标记                │ 核查结论与修正   │
└──────────── 保存草稿   提交本次核查   上一项/下一项 ─────────────┘

原文区域应得到最大的可用空间。支持折叠导航、拖动分隔线、全屏看图；窄屏可切换“原文/记录”，不能压成看不清的缩略图。首版优先桌面浏览器。
PDF显示物理页及论文印刷页（若可识别，分别标明），证据定位能直接跳到目标。Word按段落、表格、图片出现实例定位；如后续增加排版预览，只作为衍生视图，原生定位仍保留，不伪造Word物理页码。
引用片段旁边保留展开前后段落及图注的入口，避免只看被截取的一句话。正文和SI冲突时可以并排查看两份证据。原始英文与辅助翻译分开，翻译不替代证据。

7.3 科研核查顺序
第一步确认对象：是不是论文最终双功能材料，变体是否正确，是否误用了前驱体或对照。
第二步确认实验：处理什么污染物，使用什么活性组分/催化剂和氧化剂，属于哪个装置与工况。
第三步确认结果：指标指什么、数值和单位是否正确、时间窗口与采样相是否一致。
第四步确认配对：蒸发与催化是否在同一体系同期发生；展示的两个数值能否按原文归在同一条件组。页面用中文解释，J/P编码只放详细信息中。
第五步查看稳定性和结论：循环、连续运行、储存、再生、浸出分别展示，避免一项结果代表全部稳定性。
最后按选定主要性能图反向查漏：图中是否存在抽取结果没有覆盖的重要最终材料或结果。

7.4 结果卡片内容
卡头：最终材料名称、变体、实验名称、核心结果所属用途。
主要结果：原文指标名称、中文解释、数值、单位、作者报告/图读估计/计算/推断来源。
条件摘要：污染物及浓度、活性组分、氧化剂与剂量、光照/热条件、时间、体积和面积依据、采样相；未报告状态直接显示，不伪装成空白输入框等待人填。
配对摘要：同时运行证据、数值配对依据、不能确认之处。
证据：正文/SI位置、图表编号、支持当前结果的片段；一键跳转原文。
已有问题：模型发现的源文冲突、缺失或阅读限制。模型审查意见可折叠，避免先入为主；不是人必须逐项解决的清单。

人工可以确认卡片中明确选择的范围，如数值/单位、实验归属、条件或证据支持。界面记录选择范围，不因点击一个数值正确就把整张卡片所有条件标为已核。

7.5 人工动作及含义
“与原文一致”：增加该项、该范围、该版本的核查记录，不改变科学数值，也不提升其他记录的验证状态。
“修正”：修改数值、单位、状态、材料归属、实验归属或证据；保存原值、修改值、原文位置和理由。改变实验归属时，展示共同条件、配对和相邻结果的受影响范围。
“已核查来源中未报告”：登记该字段在明确核查范围内未报告；附件未取得、未读或看不清不能使用此选项冒充作者未报告。
“原文冲突”：保存双方事实和各自证据，不要求人任选一个高值；必要时限制相关结果参与比较。
“暂不能判断”：保留未解决或不可读状态，既不算正确，也不自动算抽取错误；可以提交其他已完成项。
“补充遗漏”：在原文中标注遗漏的材料/实验/结果，手填简短说明或请求模型据此补抽；模型补抽经自动审查后展示差异，不能自动标成人工认可。
“请求模型回查”：指定问题和原文范围，形成有预算的后台回查任务。返回建议、证据与差异，不静默覆盖当前版本。
“不应作为本篇结果”：用于误抽参考文献或错误对象等情况，保留原记录及否定依据，在新版本中撤下其有效性，不删除历史证据。

普通确认可一键完成；修改和否定需有简短依据或明确原文定位。只看过文件、自动保存草稿或模型再次同意都不算人工提交。

7.6 反向查漏
入口从原文的主要性能图/表开始，展示图中主要最终材料、工况与现有记录的对应列表。人工可标注“已覆盖”“存在漏项”“暂不能判断”。
仅登记这一张图或选定范围的查漏结果，不宣称整篇所有实验均已覆盖。即使6项数值全部核对正确，只要没有完整原文目标清单，也不能据此计算整篇召回率。

7.7 提交流程
提交前展示：本次核查范围、确认项、修改项、未判断项、未核查项、反向查漏范围，以及会影响哪些实验或入库数据。
保存草稿只保存当前工作；提交后登记审核人、时间、被审版本、对象与字段、结论、证据、理由及内容指纹。首版可使用明确的本机审核人名称，不需要复杂审批组织。
只有确认而未改事实：保存审核记录，按策略同步审核元数据，不重新抽取全文，也不制造重复材料节点。
涉及事实修正：生成新的JSON记录版本，执行结构/来源/关系检查；配对或实验关系变化时触发相关自动回查。人明确作出的原文裁决不能被后续模型静默改回，模型有异议需作为差异保留。
模型辅助生成的其他变化继续保留模型来源，不能继承人的核查标签。只检查过的内容和对象关联保持不变时，原审核结论才可沿用；其余标记“旧核查不适用于当前变化”。
页面显示“最新记录版本”和“图谱当前版本”。新版本尚未同步时显示待同步；成功后才显示一致。同步失败不影响审核记录保存，也不能误报数据库已更新。
如果后台已有更新，提交时展示版本冲突与差异，避免旧页面覆盖新结果。历史抽查结论保留，不追改成当前结论。

7.8 人工审核的作用边界
直接作用是核查或修正所选内容；另设“建议改进通用规则”入口归纳重复错误。规则变更需单独形成版本并验证，再由模型定向回查受影响记录。
审核不会自动改变Codex权重；少量抽查不等于393篇已经逐篇验证。发现系统性问题优先改进工具或规则并自动回查，不把整批改成人工补录。

八、数据与入库页

布局：顶部筛选批次、材料类别、污染物、状态和版本；中央为结果列表；右侧为准入检查、版本差异和同步操作；详情页按最终材料、实验、性能、稳定性、证据分栏。
列表显示论文、最终材料、污染物、自动审查状态、来源限制、人工抽查范围、最新JSON版本、当前图谱版本。能导出完整JSON和人可读结果，不要求用户查看原始JSON才能理解结果。

批次可选择“自动审查完成且准入检查通过后自动入库”或“先集中查看再批量入库”。默认建议前者；选择一次策略后不逐篇要求人工批准。未被人工抽中的论文正常保留“未经人工抽查”标记，不构成阻断。

拟定常规准入要求：来源与版本可追溯；记录结构及对象/实验关系检查通过；必要模型审查已完成；没有尚未纠正的明确不支持断言；结果对应当前选定来源版本；质量限制随记录保留。人工核查不是必要条件，字段全有数值也不是必要条件。
原文缺失或冲突已经忠实记录的结果可以入库。局部关键歧义限制相关字段/实验参与数值比较或设计推断，不无差别拒绝整篇。对无法确认最终材料或论文归属等整体身份问题，保留来源登记但暂不进入常规科学查询结果。
未完成、预算耗尽、失败结果可以保存在记录层诊断，但不能伪装成已完成科研结果进入常规可用视图。

完整记录和证据留在文件记录层，Neo4j承载检索所需对象、关系与轻量状态；不为每个词或每条字段单独建立节点。
每个图谱快照对应明确的来源、记录和规则版本。新快照写入成功并核对后，才切换该论文的当前有效版本；失败保留上一个有效版本。重复导入相同版本不产生重复论文/材料。
查询默认仅使用每篇当前有效版本，历史版本可追溯但不重复计数。不能直接改图谱一个数值而让JSON、证据和审核记录仍停在旧版。
新版修订、来源更新或规则更新尚未同步时显示具体原因。对已知有错误的旧版相关结论，即使新版本暂未成功写入，也应显示待更新并限制其参与关键比较。

九、文献问答页

布局：左侧为问题历史与检索范围；中央为输入框、回答和比较结果；右侧为证据列表，可打开文献、实验详情或原文。顶部显示所用数据版本和范围，避免把未入库/未取得材料说成已检索。

默认检索当前有效的入库结果；用户可以显式选择某篇最新未入库结果进行单篇问答，页面始终标明范围。后台读取图谱关系、完整JSON和必要原文证据，不能只根据图谱节点名称生成回答。

主要问题类型：
1. 查材料：“哪些最终双功能材料在同一体系中处理过四环素？”回答材料、活性组分、氧化剂、实验及来源。
2. 查对应关系：“使用PMS的体系处理了哪些污染物？”按污染物—催化剂/氧化剂—材料—实验呈现。
3. 比较性能：“这些材料的蒸发率、催化效果和稳定性有什么差别？”并列条件与指标含义；缺少关键条件时说明不能严格排序。
4. 查原文：“某个降解率来自哪张图？有没有补水修正？”定位对应来源，必要时进行有预算的主动回查。
5. 提设计线索：“这些材料的结构或组分有哪些共同点？”区分文献事实、跨文献关联和模型提出的可检验假设。

回答中的数值、材料关系和结论附可点击证据，关联文献、具体实验、指标和版本。点击后直达原文或结果卡，不只给论文标题列表。
同名缩写按每篇定义消歧；材料分类采用多个轴和多标签，不强迫所有材料归入MOF或生物质。引用的综述结论与实验论文实测分开。
不把降解率、去除率、矿化率、冷凝水纯度混为一个指标；不把单位不一致或时间不同的结果直接比较；不将独立最优蒸发值与催化值拼接。
回答“同一体系同时实现”时检查同步运行证据；回答成对性能时额外检查数值配对依据。原文未报告不是0，不作为条件相等；没有稳定性数据不是稳定性差。

问答默认只读。发现疑似错抽时，可点击“提交回查建议”，进入后台回查和版本流程；问答会话不得直接静默修改记录或Neo4j。问题上下文可以持续，但每次回答标明当前使用的数据范围；版本变化后旧回答保留历史标记，相关缓存不能继续冒充最新结果。
首版不默认引入外部网页事实。未来若开放库外知识，需分别标明库内证据、外部来源和模型假设，不能把库外候选写成已经验证的本库材料。

原130篇单功能材料的开发路径分析、库外组分建议、特征矩阵和降维视图作为后续扩展。数据接口保留组成、结构、制备、条件与证据状态；未报告值不填0进入降维。降维邻近不解释为性能因果或可合成性证明，初版问答不宣称已经完成可靠材料推荐模型。

十、设置、服务和版本管理

设置页集中管理代码/数据/文献目录、新Neo4j连接、固定模型、任务预算、抽样数量和入库策略。默认使用现有新工程、新数据目录和新业务数据库，不自动迁移旧实例数据。

建议逻辑层次：浏览器负责交互；后台服务负责来源和版本、任务状态、抽查提交及查询；持久化任务执行器负责长时间模型调用；现有阅读工具负责取证；记录层保留原件/JSON/证据；Neo4j提供当前可用关系检索。框架与部署依赖在实施前确定，本规划不先安装或绑定新技术。

后台任务区分附件识别、全文抽取、按问题回查、图谱同步和问答；分别记录进度、结果和预算，避免入库失败导致已经成功的全文抽取被重复执行。问答与批量抽取都保持既定模型配置，通过队列和预算管理资源，不以静默降模型解决等待。
模型认证沿用现有正常登录方式，网页不要求用户逐篇输入凭据；数据库凭据在后台管理，不显示在普通页面或日志里。原文内容始终是证据，不能改变执行权限或触发任意命令。

四种变化分别处理：
附件角色变化：更新来源登记，评估并重新核查受影响结果。
科学字段修正：生成记录新版本，校验后同步图谱。
审核结论提交：更新明确范围的审核记录，不自动改未审核事实。
抽取规则变化：形成新规则版本和影响范围，经过验证后安排定向重抽/回查；旧结果继续标明原规则版本。

十一、典型操作流程

正常论文：选择目录 → 文件角色自动识别 → 一次选择批次处理与入库策略 → 自动阅读全文/抽取/审查/修订 → 通过准入后入库 → 在问答中使用。全过程不要求逐篇人工点击通过。

角色不确定：附件进入集中确认列表 → 查看首页和判定理由 → 选择角色或归属 → 系统登记 → 继续该篇。其他论文不受影响。

SI未取得或作者没写条件：明确记录范围和状态 → 抽取现有来源支持的内容 → 完成但有限制 → 正常入库，相关查询受相应限制。无需人工填数。

抽查发现错误：打开入选论文 → 定位结果与原文 → 提交有依据的修正或回查请求 → 新记录版本 → 校验/必要自动复核 → 同步图谱 → 后续问答使用新版，历史版本和旧审核保留。

原文冲突：并排展示两处证据 → 记录冲突与影响范围 → 不要求选出一个“正确最高值” → 允许其余有依据的数据继续使用。

入库失败：保留抽取结果与原有效快照 → 显示待同步和错误原因 → 重试同步，不重新跑全文抽取。

模型未完成：显示已完成阶段和具体中断原因 → 有预算地重试/恢复 → 成功后才进入正常入库。不能凭已经存在candidate.json就算完成。

十二、实施顺序与验收场景

阶段一：文献库、附件自动识别、证据阅读组件和任务页。复用现有C01/V10等开发来源验证常规、Word、多SI和异常路径，不先启动393篇生产任务。
阶段二：人工抽查提交、版本修订、准入规则、图谱同步与当前版本选择。抽查以少量真实文献演练，避免用“全部标为通过”演示。
阶段三：证据问答和生产批次调度。先打通检索、比较、原文回查与版本变化，再开放较大批次；增加统计、恢复与少量抽样。阶段顺序是实施安排，不是要求用户逐篇审核的门槛。
后续扩展：材料分类管理、成分/结构特征矩阵与降维、原130篇单功能材料开发路径、库外组分候选、多用户协作。

首版验收至少覆盖：
1. 原文件不改名，正常正文/SI自动登记；一篇多SI均关联正确。
2. 内容与文件名矛盾时不误强制归类；参考文献中的DOI不被当作论文身份；合并文件保留范围和单一来源身份。
3. 只有有歧义的附件进入确认列表，不要求所有论文手写映射。
4. PDF和Word证据能准确跳转、放大与展开上下文；不可读内容如实标记。
5. 结果保留正确最终材料/实验绑定、同步运行和数值配对；不拼独立最优值。
6. 未报告条件不产生编造数值、不触发无限修订或逐篇人工待办。
7. 关闭浏览器不会丢失后台任务；未完成任务不被统计为成功。
8. 抽查只记录实际范围；暂不能判断与已确认分开；能从原图提出遗漏。
9. 修正实验归属时显示相关配对/条件影响；新版本不静默继承已失效的人工核查。
10. 未经人工抽查但自动流程完成且准入通过的结果可入库；未完成结果不能伪装完成。
11. 入库幂等；同步失败保留旧有效版本；切换成功后问答不重复统计同篇多版本。
12. 问答能追溯到具体原文证据；不可比条件明确显示；发现疑点通过回查流程修正而非直接改库。
13. 来源新增、规则更新和人工修正的影响范围可见，历史数据与失败不覆盖。
14. 少量抽查报告不将未审项目视作正确，不把开发样本修好后的表现称为全库准确率。

上述验收分别检验工程行为和选定科学内容。页面功能通过、模型再次认可、证据定位匹配与少量样本核查，都不能单独证明393篇全部正确。

十三、规划交付边界

本次仅新增这份TXT规划，不修改现有抽取程序、规则提示、配置、原始文献或数据库。不创建网页原型、不执行模型任务、不启动批处理。
本规划确定默认交互与数据责任；具体页面视觉样式、框架选型、自动角色识别阈值、生产并发和质量指标阈值将在后续实施与小样本验证中确定，不能提前作为已实现或已验证能力宣传。
